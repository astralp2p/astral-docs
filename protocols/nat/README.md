# nat

The `nat` protocol performs NAT traversal, letting two nodes behind separate NATs open a direct UDP path to each other by hole-punching. A caller starts a traversal with `nat.punch`, naming the peer's identity; the peer's node answers on `nat.node_punch`, and the two sides exchange `nat.punch_signal` control messages (offer, answer, ready, go, result) to punch simultaneously. Before its offer or answer, each side reflects its punch socket off a node it dialed at a public IPv4 address with `nat.reflect_udp`, and advertises the endpoint that node observed: behind a NAT with endpoint-independent mapping, every peer reaches the socket there. A side with no such node, or whose reflection fails within 2 s, advertises its public IPv4 address and the socket's local port. During the punch each peer sends its 16-byte session to the other peer's advertised port and to the 10 ports on either side of it, 5 datagrams to each address every 25 ms, plus or minus 3 ms. A peer accepts the session from any UDP port of the other peer's advertised IP address: a NAT that translates ports sends from a port nobody advertised, and the session, not the port, proves the sender. On accepting the first such datagram a peer sends the session 5 times to the address it came from, then stops sending and reading. A punch that accepts no datagram within 10 s fails. A successful punch produces a `nat.hole` object pairing the active and passive `nat.endpoint` addresses with the local port each peer binds, which the node keeps in a pool.

Holes in the pool are enumerated with `nat.list_holes`, which streams `nat.hole` objects and can be filtered to a single peer. A held hole is handed to a consumer with `nat.node_consume_hole`, a two-phase lock-then-take handshake carried by `nat.consume_hole_signal` messages. Participation in traversal is toggled node-wide with `nat.set_enabled`.

A side picks the reflecting node from its own links: the punch peer when this side dialed it at a public IPv4 address, else the first other node this side dialed at one. An inbound link does not qualify, because its remote endpoint is the address the peer was seen from, not one it listens on. The reflected endpoint is used for this punch only.
