# nat

The `nat` protocol performs NAT traversal, letting two nodes behind separate NATs open a direct UDP path to each other by hole-punching. A caller starts a traversal with `nat.punch`, naming the peer's identity; the peer's node answers on `nat.node_punch`, and the two sides exchange `nat.punch_signal` control messages (offer, answer, ready, go, result) to punch simultaneously. During the punch each peer sends its 16-byte session to the other peer's advertised port and to the 10 ports on either side of it, 5 datagrams to each address every 25 ms, plus or minus 3 ms. A peer accepts the session from any UDP port of the other peer's advertised IP address: a NAT that translates ports sends from a port nobody advertised, and the session, not the port, proves the sender. On accepting the first such datagram a peer sends the session 5 times to the address it came from, then stops sending and reading. A punch that accepts no datagram within 10 s fails. A successful punch produces a `nat.hole` object pairing the active and passive `nat.endpoint` addresses with the local port each peer binds, which the node keeps in a pool.

Holes in the pool are enumerated with `nat.list_holes`, which streams `nat.hole` objects and can be filtered to a single peer. A held hole is handed to a consumer with `nat.node_consume_hole`, a two-phase lock-then-take handshake carried by `nat.consume_hole_signal` messages. Participation in traversal is toggled node-wide with `nat.set_enabled`.
